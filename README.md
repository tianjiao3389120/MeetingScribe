# MeetingScribe

macOS 应用：把会议录像/录音变成会议纪要。语音转录与画面识别全程在本机完成，只有生成纪要这一步调用模型。

**核心差异**：不只是转录 + 摘要。屏幕共享的内容（问题清单、告警列表、架构图）会被提取、
去重、OCR，并**按时间轴与逐字稿对齐**后一起送给模型 —— 那些数字、日期、主机名是音频里
根本不存在的信息。

## 快速开始

要求：macOS 14 或更高版本，当前构建脚本面向 Apple Silicon。

```bash
./build.sh --install       # 构建并安装到 /Applications
```

首次打开后进设置：

1. **配置大模型** —— 从下拉列表选择 OpenAI、DeepSeek、智谱、Kimi、通义、Ollama 等服务，填写模型和 API key
2. **安装转录引擎并准备识别模型** —— `brew install whisper-cpp`；模型约 1.5GB，可在线下载，也可从另一台 Mac 导入离线模型包
3. **按需调整会议纪要指令和领域词表** —— 设置里可编辑纪要要求，也可查看内置完整提示词
4. **可选：安装说话人分离** —— 约 100MB 运行环境与 28MB 模型

“识别场景”可选择普通话、英文、自动多语言或“香港粤语 / 普通话 / 英语”。香港混合场景会自动检测语言，保留英文业务术语，并把纪要整理为简体书面中文。

然后把 `.mov` / `.mp4` / `.m4a` / `.mp3` 拖进窗口即可。也可以同时选择飞书妙记导出的
`.srt`、`.txt` 和原始音频：应用会使用 SRT 的时间码与说话人信息，跳过本地语音转录和说话人分离，
直接进入纪要生成。TXT 中的会议日期与时长会作为补充元数据读取。

网络不稳定或需要部署多台 Mac 时，可在已配置设备的“设置 → AI 引擎 → 离线迁移”中导出离线引擎包，
再到新设备一键导入。引擎包包含 Whisper large-v3-turbo 与 VAD 模型；如果本机已经安装说话人
分离模型，也会同时包含分段与声纹模型。全部文件通过 SHA-256 校验完整性；
在线下载失败会保留已下载内容，再次点击时断点续传。`whisper-cli` 依赖 Homebrew 动态库，不放入
引擎包，新设备仍需单独执行 `brew install whisper-cpp`。说话人分离的 Python/sherpa-onnx 运行环境
同样不打包；导入模型后可在设置中执行安装，已导入的模型不会重复下载。

也可以在首页点击“使用系统截屏录制”，直接打开 macOS 自带的截屏与录屏工具（等同于
`Shift–Command–5`）。录制完成后，把系统生成的 MOV 拖回 MeetingScribe，或点击“选择文件”导入分析。

### 外部逐字稿导入

外部逐字稿以 SRT 为主数据，因为它同时包含起止时间、发言人和正文；同批选择的 TXT 用于补充会议
日期、时长与关键词，原始音频作为回听和未来屏幕录像同步的依据。导入外部逐字稿时不要求安装
Whisper 或说话人分离环境。


应用默认自动判断实际开口人数并进行说话人分离。自动结果不理想时，可在结果页点“重新分离说话人”，
为本次录音指定实际发言人数；逐字稿会从缓存复用，不会重新转录。

导入后可在处理前修改会议名称、选择空间和标签、填写这一次会议独有的背景，并附加会议材料。
客户或项目长期不变的背景应维护在会议空间中，不需要写成一个全局默认背景。
还可以选择客户沟通、双周会、项目评审、故障复盘或需求讨论等纪要模板；会议空间可指定默认模板。

## 依赖

| 组件 | 用途 | 安装 |
|---|---|---|
| whisper-cpp | 语音转录 | `brew install whisper-cpp` |

音轨提取、抽帧、OCR 都用系统框架（AVFoundation / Vision），**不需要 ffmpeg**。

## 大模型

生成纪要、双栏释义、同步邮件、香港繁体转换和历史待办回溯统一使用
“设置 → 大模型”中的运行方式。支持本机 Codex CLI、本机 Claude Code、OpenAI API 和智谱 GLM。
API key 存在 keychain，不落 UserDefaults；打开设置只检查凭据是否存在，不会读取密钥。

也可以在“设置 → 大模型 → 运行方式”选择“本机 Codex CLI”，复用本机已经登录的 Codex
订阅，无需在应用内保存 API key。请先安装 Codex CLI 并运行 `codex login`；MeetingScribe 会用
临时、只读任务生成纪要，不保留 Codex 会话。此模式下屏幕画面通过 OCR 文字传入。
Claude Code 同样复用本机登录；两个 CLI 后端均以文字方式接收 OCR 结果。

## 管道

```
视频 ──┬─► 音轨 (AVFoundation) ─► whisper.cpp + VAD ─► 带时间轴逐字稿 ─┐
       │                                                              ├─► 交错合并 ─► 模型 ─► Markdown
       └─► 抽帧 ─► 感知哈希去重 ─► Vision OCR ─► 带时间轴屏幕内容 ─────┘
```

模型优先输出结构化 JSON（问题、需求、待办、责任人、期限和证据时间码），应用在本地校验后
渲染为 Markdown。若某个兼容模型没有返回合法 JSON，会自动保留其原始输出，不让本次生成失败。
保存结果时会同时写出 `纪要.md`、`纪要.json` 和 `逐字稿.txt`。

## 历史会议

每次成功生成纪要后，应用会自动在本机保存一个历史版本。工具栏的“历史会议”支持：

- 三栏资料库布局：左侧智能分类与“客户 → 项目名称 → 会议类型”树、中间会议列表、右侧会议详情
- 最近 30 天、未完成待办、收藏和归档等智能分类
- 客户或项目名称未填写时统一归入“未知”；会议类型直接使用会议标签
- 用空格组合搜索标题、纪要、客户、项目名称、标签和说话人；每个条件都必须匹配
- 为已有历史记录修改会议名称、客户、项目名称和会议类型；同一源会议的所有纪要版本同步修改
- 校正历史逐字稿并直接重新生成纪要，不重新运行语音识别
- 按需生成香港粤语/普通话双栏逐字稿，保留原文并显示简体中文释义
- 应用异常退出后恢复未完成会议，并复用已有转录缓存
- 查看过去的 Markdown 纪要
- 在纪要、待办、逐字稿、同步邮件和会议信息之间快速切换
- 在待办页修改任务、责任方、截止时间和状态；完成状态会同步更新结构化记录与 Markdown 纪要
- 待办作为会议事实保存在纪要中；项目总览按问题聚合展示，只用于回看，不维护独立任务状态或触发模型回溯
- 在项目总览对单个持续跟进或已闭环问题执行一键专题分析；报告只使用已确认关联的会议与证据，以一段高度总结和可视化时间线呈现，持久保存后可再次查看，不会自动修改问题状态
- 首次升级时会一次性整理存量会议：使用已有结构化纪要替换仍沿用视频文件名的名称，并在原录屏仍存在时校正会议日期；不会覆盖人工修改过的名称
- 新导入会议优先使用录屏文件的创建日期作为会议日期，缺失时再回退到文件修改日期或导入时间
- 打开仍然存在的原始媒体，或重新处理
- 导出纪要、结构化 JSON 和逐字稿
- 删除历史副本（不影响原始媒体和此前导出的文件）

## 项目行动项台账

会议空间现在包含独立于单次纪要的项目行动项台账。每次生成结构化纪要后，应用会把新待办或明确的
状态、责任人、截止日期变化整理成“项目更新建议”；只有用户在空间总览中确认后才会写入台账。
每次确认都会保留来源会议、证据时间码和修改前后的状态，未在新会议中提及的事项不会被推断为完成。

空间总览优先展示待确认更新、未完成、逾期和阻塞事项，并把逾期/阻塞项整理为下次会议建议跟进清单。
首次打开已有空间时，会用最近一场结构化纪要生成初始台账建议，不会静默导入或修改历史数据。

历史库不会复制原始媒体或保存屏幕截图；同一会议重新生成会保留为独立版本。源文件被移动后，
已有纪要仍可正常查看。数据位于：

```text
~/Library/Application Support/MeetingScribe/Meetings/
```

这里是应用的权威内部记录。结果页保存到原媒体旁边、或历史页“导出”产生的文件都是独立副本；
移动或删除导出副本不会影响历史库，修改历史分类也不会重写外部副本。

设置中的“存储管理”会分别统计历史资料库、托管材料、转录/说话人缓存及
说话人运行环境，支持打开资料库目录、识别已经移动的源文件并清理处理缓存。
还可以创建完整 ZIP 备份并合并恢复会议、托管材料、会议空间、反馈和声纹档案；
缓存、说话人运行引擎和钥匙串中的 API Key 不进入备份，恢复也不会覆盖当前已有的数据。
自动备份可选择 iCloud Drive 或其他本地目录，支持每天或每周检查并保留最近指定数量的备份；
检查发生在应用启动和会议处理完成后，应用关闭时不会安装或运行额外的后台任务。

## 会议分类、项目资料与会前材料

每场会议独立保存客户、项目名称和会议类型；会议类型直接使用标签。客户和项目名称既可从历史
数据中选择，也可手动新增。匹配到已有项目资料时，应用会在后台自动复用长期背景、默认模板、
识别学习和待办跟踪能力；项目资料关联不参与资料库分类。

选择音视频后会先进入“准备会议分析”，可附加本次材料：

- PDF
- TXT、Markdown、CSV、JSON
- PNG、JPEG

PDF 和文本在本机提取文字，图片在本机 OCR；支持视觉的模型还会收到图片原件。材料会以
`材料：文件名` 标记为独立事实来源。单次最多 12 份、提取文字总计 2.4 万字，防止挤占逐字稿
上下文。成功生成纪要后，材料原件会复制到该会议的内部历史目录；外部原件移动或删除后，
历史重新处理仍然可用。删除会议历史时，其托管材料也会一并删除。

几个设计选择：

- **抽帧用固定间隔 + 感知哈希过滤，而不是 ffmpeg 的场景切变检测。** 录屏里鼠标移动和
  摄像头小窗会让场景检测疯狂误触发；dHash 对这类局部变化几乎不响应，对真正的翻页却
  变化剧烈。实测去重率约 85%。候选画面使用固定容量池，长会议不会因频繁切屏无限增长内存。
- **文字型画面走 OCR 文本，图表型画面才发原图。** 仪表盘截图当图片发要上千 token，
  当文字发只要几百；而架构图靠布局传意，OCR 出来只是一堆散落标签。按识别出的文字量
  自动分流。
- **画面与逐字稿按时间轴交错**，模型才能把某句话和当时屏幕上的内容对上。

## 说话人分离与声纹

应用默认进行说话人分离，在本机使用 sherpa-onnx、
pyannote 分段模型和 3D-Speaker CAMPPlus 声纹模型，把发言归入“说话人 A/B/C”。

首次登记姓名：

1. 在设置中安装说话人分离模型。
2. 处理会议后，在结果页选择“登记或更新说话人声纹”。
3. 试听代表片段、填写姓名，点击“保存并重新生成纪要”。

姓名会立即用于当前纪要，后续会议会自动尝试声纹匹配。可在
`设置 → 说话人分离 → 已登记声纹 → 管理` 中改名或删除。如果自动聚类数量不合理，
在结果页点“重新分离说话人”并指定实际发言人数；转录会从缓存复用。

## 缓存与重试

- 转录和说话人分离分别缓存，重复处理时无需重算昂贵阶段。
- 语言、词表、模型、关键参数或缓存 schema 改变时，缓存 key 会自动变化。
- 模型调用失败后可只重试生成纪要，逐字稿和画面仍会保留。
- 设置中的“清除缓存”同时清理转录和说话人缓存，不会删除声纹档案。

## 命令行

App 自带 headless 模式，传文件路径即可（纪要走 stdout，进度走 stderr）：

```bash
/Applications/MeetingScribe.app/Contents/MacOS/MeetingScribe 会议.mov > 纪要.md
```

只要逐字稿不要纪要：

```bash
./transcribe.sh 会议.mov      # 输出 txt + srt
```

## 词表

`设置 → 领域词表` 的内容会作为初始提示注入语音识别，能显著改善专业术语的识别准确率。

词表目前由用户手动维护，应用不会根据识别结果自动增删，避免错误词反向污染后续会议。
跨会议稳定的领域术语放在这里；某个客户或某场会议独有的人名、产品名和缩写，优先通过
会议空间背景、当次会议背景或会前材料提供。

生成纪要后可点“反馈”记录问题，也可把错词提交为待审核术语。候选词只会出现在设置中，
必须由用户确认后才会加入领域词表；填写具体修改要求时可直接复用转录结果重新生成纪要。

结果页和历史会议还可以生成同步邮件：先按客户、内部同事或合作伙伴以及正式、自然、简洁语气
生成简体中文草稿；人工核对并编辑后，再基于确认稿生成香港繁体商务版。两个版本会保存在会议
历史中，支持复制以及导出 TXT/Markdown；应用不会自动发送邮件。
中文草稿采用阶段工作同步结构：先给出整体总结，再逐项列出带状态的问题与故障，最后整理需求、
状态和时程；香港繁体版会保留该结构并调整为香港项目邮件常用措辞。
邮件模板会默认跟随纪要模板：双周会使用阶段性工作同步，客户沟通、项目评审、故障复盘和需求
讨论分别使用对应的邮件结构。邮件窗口可临时切换，会议空间也可以指定默认邮件模板。

写法要点：**写成通顺的句子而非散词罗列**（whisper 对前者响应明显更好），170 字以内。
每次发现新错词就补进去。

命令行版本读 `glossary.local.txt`（不入库），没有时回落到 `glossary.txt`。

## 转录参数

关键参数在 `Pipeline/Transcriber.swift`，经真实会议实测定型：

```
--vad --vad-model ggml-silero-v5.1.2.bin -vmsd 12 -vsd 220 -mc -1
```

- **VAD 是最大的单项收益** —— 静音段不再喂给模型，幻觉循环（连续几十遍重复同一句）
  基本消失，同时耗时减半。质量与速度没有取舍。
- **不要设 `-mc 0`** —— 灭幻觉的功劳全在 VAD；关掉上下文只会让术语准确率明显下降。
- **`-ml` / `-sow` 在 VAD 模式下无效** —— 分段由语音边界决定，这两个参数被绕过。
  控制片段粒度要用 `-vmsd`（单段最长秒数）和 `-vsd`（静音切分阈值）。

## 开发与验证

```bash
swift test                 # 单元与回归测试
swift build -c release     # Release 编译
./build.sh                 # 打包到 build/MeetingScribe.app
./build.sh --install       # 打包并安装到 /Applications
```

本机默认使用 ad-hoc 签名。分发构建可设置 Developer ID：

```bash
MEETINGSCRIBE_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" ./build.sh
```

脚本会启用 Hardened Runtime 和可信时间戳；正式对外分发还需使用 Apple notary service 公证。

CI 会在每次 push 和 pull request 上运行测试及 Release 构建。

## 隐私

- 音频、画面、OCR 全在本机，不出网
- 可选的声纹档案属于敏感生物特征，仅保存在本机应用支持目录，文件权限限制为当前用户可读写；可在设置中查看、改名或删除
- **只有最后生成纪要这一步**会把逐字稿和选中的截图发给模型
- API key 保存在 macOS Keychain；远程自定义接口必须使用 HTTPS
- 如果会议内容涉及客户生产环境（IP、主机名、架构），发送前请确认合规要求
