# MeetingScribe

MeetingScribe 是一款 macOS 本地会议分析应用，可将会议录像、录音或外部逐字稿整理为结构化会议纪要，并持续维护项目问题、待办、人员角色、识别记忆和声纹资料。

它不只做“转录 + 摘要”：应用会在本机提取屏幕画面、OCR 文字和说话人信息，按时间轴与逐字稿对齐后，再由所选模型生成纪要。正式项目中的历史问题会先经过本地检索，只把少量相关候选交给模型判断，避免会议越多、上下文越大。

## 主要能力

- 本地提取音轨并使用 whisper.cpp + VAD 转录
- 本地进行说话人分离、声纹匹配、抽帧、图片去重和 OCR
- 支持普通话、英文、自动多语言及香港粤语/普通话/英语混合识别
- 根据逐字稿和屏幕内容生成结构化纪要、问题、需求和待办
- 按客户、正式项目和会议标签管理历史会议
- 跨会议关联项目问题，并维护状态、证据和完整时间线
- 通过识别记忆持续学习人名、术语和已确认纠错
- 统一管理我司人员、客户联系人、角色和本地声纹
- 提供测试版与正式版两个相互隔离的数据环境
- 提供隐藏的数据流调试日志，可查看每个节点和模型的完整输入输出

## 系统要求

- macOS 14 或更高版本
- Apple Silicon Mac
- `whisper-cpp`：`brew install whisper-cpp`
- 可选：Homebrew Python 3，用于安装固定版本的说话人分离运行环境与模型
- 至少配置一种纪要生成方式：Codex CLI、Claude Code、OpenAI API 或智谱 GLM

音轨提取、抽帧和 OCR 使用 AVFoundation、Core Image 和 Vision，不依赖 ffmpeg。

## 构建与安装

```bash
./build.sh                       # 构建测试版
./build.sh --install             # 构建并安装测试版
./build.sh --production          # 构建正式版
./build.sh --install-production  # 构建并安装正式版
```

构建产物：

- 测试版：`build/MeetingScribe.app`
- 正式版：`build/MeetingScribe Production.app`
- 安装位置：`/Applications`

本地构建默认使用 ad-hoc 签名。Developer ID 构建可以设置：

```bash
MEETINGSCRIBE_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" ./build.sh
```

发布时可以通过 `MEETINGSCRIBE_VERSION` 和 `MEETINGSCRIBE_BUILD_NUMBER` 设置版本：

```bash
MEETINGSCRIBE_VERSION=1.0.0 MEETINGSCRIBE_BUILD_NUMBER=1 \
MEETINGSCRIBE_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
./build.sh --production
```

正式对外分发仍需提交 Apple notary service 公证并 stapling；不应将默认 ad-hoc 签名产物作为公开下载版。

## 测试环境与正式环境

两个 App 可以同时安装：

| 环境 | App 名称 | 数据目录 |
|---|---|---|
| 测试版 | 会议纪要 · 测试 | `~/Library/Application Support/MeetingScribe/` |
| 正式版 | 会议纪要 · 正式 | `~/Library/Application Support/MeetingScribe-Production/` |

正式版首次启动时，会一次性继承稳定的基础资料和处理设置，包括：

- 客户与项目资料
- 我司人员、客户联系人和角色
- 声纹档案
- 识别记忆
- 模型运行方式、转录性能等基础设置

正式版不会复制测试会议、项目问题与待办、用量统计、调试日志或处理缓存。两个环境共享本地 Whisper、VAD 和说话人模型，避免重复占用数 GB 磁盘。

## 首次配置

打开“设置”后，建议依次完成：

1. 在“AI 引擎 → 纪要生成”选择运行方式。
2. 使用 API 时选择 OpenAI 或智谱 GLM，保存 API Key 并测试连接。
3. 在“AI 引擎 → 本地识别 → 语音转录”确认 whisper.cpp 和模型状态。
4. 按需要安装说话人分离运行环境及模型。
5. 选择画面采样密度和转录性能模式。

本机 CLI 模式会复用已经登录的 Codex CLI 或 Claude Code，不需要在应用中保存 API Key。API Key 使用 macOS Keychain 保存，不写入 UserDefaults。

网络不稳定或需要部署多台 Mac 时，可以从“设置 → AI 引擎 → 离线迁移”导出和导入识别引擎包。引擎包包含 Whisper、VAD，以及本机已有的说话人模型，并通过 SHA-256 校验完整性；Homebrew 的 `whisper-cli` 和说话人 Python 运行环境仍需在目标 Mac 安装。

## 导入会议

支持以下输入方式：

- 拖入或选择 `.mov`、`.mp4`、`.m4a`、`.mp3`
- 同批选择飞书妙记等工具导出的 `.srt`、`.txt` 和原始音频
- 点击“录制会议”打开 macOS 系统录屏工具，录制完成后再导入生成的文件

外部逐字稿以 SRT 为主数据，因为它包含时间码、说话人和正文；TXT 用于补充日期、时长或关键词，原始音频用于回听和后续处理。存在有效 SRT 时，应用会跳过本地语音转录和说话人分离。

## 会前准备与正式项目

导入后会进入“准备会议分析”。这里可以设置：

- 会议名称
- 识别场景
- 正式项目关联
- 本次会议类型/标签
- 本次会议材料
- 本次纪要侧重点
- 本次补充说明

“正式项目关联”决定会议是否进入项目级问题和待办机制：

- 选择已有正式项目后，会复用项目长期背景、历史标签、识别记忆、问题和待办。
- 没有合适项目时，可以展开“新建项目”，填写客户、项目名称、初始标签和长期背景后创建并关联。
- 不选择正式项目也可以生成纪要，但本次不会写入项目问题和项目待办。

会议标签只在选择正式项目后出现，并优先提供该项目过去使用过的标签。项目长期背景用于后续所有相关会议；“本次补充说明”只用于本次纪要，不会反向修改项目资料。

纪要侧重点默认使用“通用会议”。本次选择会直接覆盖默认值，不存在项目级默认纪要模板。

### 本次会议材料

“更多选项”中可以附加：

- PDF
- TXT、Markdown、CSV、JSON
- PNG、JPEG

PDF 和文本在本机提取文字，图片在本机 OCR。支持视觉的 API 模型可同时接收筛选后的图片原件；Codex CLI、Claude Code 和不支持视觉的模型只接收 OCR 文字。

单次最多 12 份材料，提取文字总计最多约 2.4 万字。成功生成纪要后，材料原件会复制到会议内部历史目录，外部原件移动后仍可重新处理。

## 数据处理流程

```text
音视频
  ├─ 本地：提取音轨 → Whisper + VAD → 转录 → 识别记忆纠错
  │                                      └─ 说话人分离与声纹匹配
  └─ 本地：扫描视频 → 抽帧 → 感知哈希去重 → OCR / 图片筛选
                                             │
逐字稿 + 说话人 + OCR + 材料 + 筛选后的图片 ──┴─→ 纪要生成模型
                                                        │
                                                        ├─→ 结构化纪要与 Markdown
                                                        └─→ 项目问题关联
                                                              ├─ 本地 BM25 候选筛选
                                                              └─ 模型判断关联/新建/复发
```

模型优先返回结构化 JSON，包含问题、需求、待办、责任人、期限和证据时间码。应用在本机解析、校验并渲染为 Markdown；兼容模型若没有返回合法 JSON，会保留原始输出，不让整场会议丢失。

生成结果会保存内部结构化记录、Markdown 纪要和逐字稿。同一源会议重新生成时保留多个版本，可在版本窗口切换，或只保留当前版本并清理其他版本。

## 哪些内容会发送给模型

音频提取、Whisper 转录、说话人分离、声纹匹配、抽帧、OCR、识别纠错和 BM25 检索都在本机完成。以下功能会调用当前选择的生成模型：

| 模型节点 | 主要输入 | 用途 |
|---|---|---|
| 关键画面规划 | 候选时间段及相邻逐字稿 | 判断哪些时间点值得进一步取图 |
| 纪要生成 | 逐字稿、说话人、项目/本次背景、材料文字、OCR，以及受支持时的筛选图片 | 生成结构化纪要 |
| 问题关联 | 本次结构化问题和本地筛出的少量历史候选 | 判断新建、关联或闭环问题复发 |
| 问题专题分析 | 已确认的问题历史、会议证据和已有分析 | 生成问题全貌、最新进展和完整时间线 |

因此，“本地识别”不等于整条流程完全离线。使用在线 API 前，应确认会议内容符合组织和客户的数据合规要求。

## 画面处理

录屏画面采用固定间隔扫描和感知哈希去重，而不是依赖场景切变。这样可以减少鼠标移动、摄像头小窗和轻微动画造成的误判。

画面会按内容分流：

- 文字型画面主要使用 OCR 文本，降低图片 Token 消耗。
- 架构图、拓扑图等依赖空间关系的画面，在视觉模型可用时保留原图。
- OCR 结果仍作为可检索和可核对的补充，不用它替代原图表达布局。
- 画面和逐字稿按时间轴对齐，避免把屏幕内容关联到错误讨论段落。

画面提取会持续报告扫描进度，固定采样密度可以在本地识别设置中调整或关闭。

## 会议资料库

资料库采用三栏布局：左侧分类、中间会议列表、右侧会议详情。

主要能力：

- 最近会议、全部会议、待办未完成、收藏、归档等智能分类
- 按“客户 → 项目 → 会议标签”展开历史会议
- 按最新、最早或名称排序，并按标签和状态筛选
- 搜索会议名称、纪要、客户、项目、标签和说话人
- 查看“会议纪要、待办、信息”三个详情页
- 编辑会议名称、客户、项目、标签和会议时间
- 修改说话人姓名、所属方和角色，可仅保存或重新生成纪要
- 校正识别结果，可仅学习供后续会议使用，也可重新生成纪要
- 打开源文件、重新定位源文件、复用内部逐字稿重新生成
- 导出会议纪要、内部完整纪要、逐字稿或全部会议资料
- 收藏、归档、删除记录和清理旧版本

会议列表以源会议为稳定行，同一会议的版本切换不会改变列表排序或让选中行跳动。

## 项目问题与待办

选择正式项目后，结构化纪要中的问题和待办会进入该项目的跨会议台账。

### 问题关联

问题关联是独立于纪要生成的步骤：

1. 纪要先生成本次问题。
2. 本机 BM25 根据问题名称、别名、检索词、历史综合摘要和排除词计算相关度。
3. 每个本次问题只选择少量未闭环候选和必要的已闭环复发候选。
4. 模型只在这些候选中判断关联、新建或复发，并更新滚动综合摘要。
5. 高置信结果可自动确认；重复、从属、边界不清或已闭环复发等情况会要求人工确认。

可以在高级诊断中开启“生成最终纪要前始终确认问题”；关闭时只在存在歧义时暂停。手动搜索关联会显示问题状态，已闭环问题不会与未闭环问题混在一起而无法判断。

项目问题支持：

- 修改问题名称
- 手动关联或新建问题
- 标记闭环、重新打开和维护状态
- 添加重点问题星标
- 保留每次会议的进展、证据和状态变化
- 基于已确认历史生成问题专题分析

专题分析展示“问题全貌”“最新进展”和可折叠的“完整时间线”。完整时间线按会议保留当时情况和下一步；重新分析只更新专题档案，不修改问题状态和历史事实。

### 待办台账

单次会议待办保留在对应纪要中，可以修改任务、责任方、截止时间和状态。正式项目还维护跨会议行动项及其来源会议、状态变化和证据；没有在新会议中提到的待办不会被自动推断为完成。

## 识别学习与本地纠错

“设置 → 识别学习 → 识别记忆”统一管理术语、人名、公司、产品和缩写。

识别记忆分两种用途：

- **识别提示**：正确词会进入 Whisper 初始提示，提高后续识别概率。
- **自动纠正**：明确的“错误写法 → 正确写法”会在转录后进行本地替换。

每条记忆会显示被送入识别提示的次数和实际完成自动纠正的次数。记忆可以作用于所有会议，也可以只作用于指定正式项目；项目级记忆不会污染其他客户或项目。

在结果页使用“纠正并学习”时，可以：

- 仅保存，下次会议生效
- 保存并重新生成当前纪要

手工词表仍保留用于兼容旧设置，但新的术语和纠错应优先放入识别记忆。Whisper 初始提示会去重并限制长度；提示只提供正确词汇，不把类似“星盾诶应识别为星盾AI”的指令句直接交给 Whisper。

## 说话人、角色与声纹

应用使用本地 sherpa-onnx、pyannote 分段模型和 3D-Speaker CAMPPlus 声纹模型进行说话人分离和匹配。

会议完成后，可在“修改说话人姓名与角色”中：

- 合并同一人的多个临时说话人片段
- 设置姓名、所属方和角色
- 将我司人员设为全局身份，在所有客户中复用
- 将客户联系人限定在对应客户范围内复用
- 仅保存供后续会议使用，或保存并重新生成当前纪要

“会议资料库 → 左上角文件夹齿轮”统一管理：

- 我司人员及默认角色
- 客户、正式项目和长期背景
- 客户联系人及角色
- 与人员绑定的本地声纹样本

人员信息和声纹信息默认折叠，减少敏感信息暴露。声纹样本质量不足、混入多人或噪声过大时，只保存姓名和角色，不把低质量片段加入声纹档案。

声纹识别无法完全替代人工确认；会议设备、距离、噪声和重叠发言变化较大时，应以当前会议的人工修正为准。

## 转录性能

“设置 → AI 引擎 → 本地识别 → 语音转录”提供四种模式：

| 模式 | 行为 |
|---|---|
| 高性能 | 使用更多 CPU 线程和 GPU，速度优先 |
| 平衡（推荐） | 降低 CPU 并发，兼顾速度和温度 |
| 安静 | 进一步限制 CPU 线程，保留 GPU |
| 极致安静（仅 CPU） | 禁用 GPU，温度更低，但速度会明显下降 |

这些模式不切换 Whisper 模型、不降低 VAD 或解码质量，主要通过线程数量和 GPU 使用方式调整性能与发热。

当前关键参数位于 `MeetingScribe/Pipeline/Transcriber.swift`：

```text
--vad --vad-model ggml-silero-v5.1.2.bin -vmsd 12 -vsd 220 -mc -1
```

VAD 会跳过静音并减少重复幻觉；保留上下文有助于专业术语和连续语义识别。模型、语言、提示词、解码参数或缓存 schema 改变时，转录缓存 Key 会自动变化。仅调整线程数量或 GPU 使用方式不会让已有逐字稿缓存失效。

## 缓存、恢复与备份

- 转录和说话人分离分别缓存，重复生成纪要不必重新执行昂贵阶段。
- 纪要模型调用失败时，可以复用内部逐字稿重新生成。
- 问题关联失败时，可以单独重试问题关联，不必重新转录或重做纪要。
- 应用异常退出后会保留可恢复任务。
- “设置 → 存储 → 管理存储”可查看历史库、托管材料和缓存占用。
- 完整 ZIP 备份包含会议、材料、客户/项目、反馈、问题待办和声纹档案；识别记忆当前不包含在备份包中。
- API Key、本地引擎运行环境和可重新生成的缓存不进入备份。
- 自动备份可使用 iCloud Drive 或其他本地目录，并按保留数量轮换。

删除会议历史不会删除原始媒体；删除缓存不会删除会议、识别记忆或声纹档案。

## 数据流调试

需要检查提示词、模型输入或耗时节点时，可在：

`设置 → 高级诊断 → 展开诊断选项`

开启“启用隐藏的数据流调试日志”。调试内容不会在界面展示大段文字，而是写入本地 Debug 目录。

```bash
# 测试版
tail -f "$HOME/Library/Application Support/MeetingScribe/Debug/latest.log"

# 正式版
tail -f "$HOME/Library/Application Support/MeetingScribe-Production/Debug/latest.log"
```

日志包括：

- 节点完整输入和输出
- 节点进度与阶段耗时
- 外部引擎路径、参数、实时 stderr、stdout 和退出码
- 每次模型调用的 Prompt ID、模型、用途和 Token 信息
- 缓存命中、发送图片数量、问题候选数量和运行汇总

打开“每个节点运行中暂停确认”后，日志会打印对应的 `touch ".../continue"` 命令。检测到文件后会记录 `TERMINAL CONTINUE RECEIVED`，删除继续文件并恢复执行。

调试关闭时不会写入完整输入输出，也不会改变正常业务流程。

## 命令行

测试版 App 支持传入媒体路径，以 stdout 输出纪要、stderr 输出进度：

```bash
/Applications/MeetingScribe.app/Contents/MacOS/MeetingScribe 会议.mov > 纪要.md
```

只生成逐字稿：

```bash
./transcribe.sh 会议.mov
```

## 隐私与安全

- 音频提取、语音转录、说话人分离、声纹、抽帧和 OCR 在本机完成。
- 声纹属于敏感生物特征，只保存在本机应用支持目录，并限制为当前用户读写。
- 在线模型只接收对应节点需要的内容；问题关联先在本地缩小历史候选范围。
- CLI 模式以文字方式接收画面 OCR，不发送图片原件。
- 支持视觉的 API 模型可能接收筛选后的图片原件和本次添加的图片材料。
- API Key 保存于 macOS Keychain；自定义远程接口必须使用 HTTPS。
- 调试日志可能包含完整逐字稿、提示词和文件路径，排查结束后应关闭调试并按需清理 Debug 目录。

完整的数据处理边界、备份风险和删除说明见 [PRIVACY.md](PRIVACY.md)；安全问题请按 [SECURITY.md](SECURITY.md) 私密报告，不要将会议数据附在公开 Issue 中。

## 当前边界

- App 不直接录制屏幕，只负责打开 macOS 系统录屏工具并导入录制结果。
- 说话人聚类和声纹匹配会受到重叠发言、回声、噪声与设备变化影响，关键会议仍建议人工核对。
- 会议纪要和问题关联依赖模型输出，应用会执行结构化校验与风险确认，但不能代替业务负责人最终判断。
